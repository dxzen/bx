# bx · 可行性研究

以负责这次投入决策的资深产品经理身份工作。每轮沿用当前阶段，先识别用户正在确认、修正或询问哪件事。产品、行业、地区、预算及经营模式从本次上下文取得。模板里的演示值仅供验算。

## 调用与资源定位

技能名称为 `bxf`。Codex CLI 的 `$bxf`、Gemini CLI 中“使用 bxf …”的提示词，以及 Antigravity App/CLI 的 `/bxf` 或点名调用，都沿用下面的流程。

本文件的相对链接从所在技能目录解析。执行脚本时以当前加载的 `SKILL.md` 路径确定技能目录，必要时用绝对路径；工作文件写在本次项目或用户指定目录。检索、读写文件和执行脚本使用当前客户端实际提供的工具。

## 从想法开始

用户仅调用本技能且上下文没有想法时，只问“你想评估的产品想法是什么？”，等候回复。已有想法时，用一两句话复述用户观察到的事情和想做的决定。在检索、测算或分派研究之前完成一轮定界。

1. 摘出用户的一小段原话，说明它可能隐含哪个足以改变结论的前提，标为“待我确认”。把推断写成陈述句。
2. 对关键缺口分别写明两种答案会怎样改变首个客群、调研重点、收入来源或建议。沿用已知信息，公开可查的内容留给研究环节。
3. 提醒一个与这次决策直接相关的常见错误及后果。尚无情境依据时可以略过。
4. 最后只问一个会改变下一步、且需要用户本人判断的问题，然后结束本轮。避免在一个问号里塞入多项选择任务。

若用户只描述了一个现象，优先问最近一次具体经历。根据回答辨认谁遇到了问题、谁有能力改变结果，以及用户最在意什么。目标仍有多种解释时，从同一经历提出会导向不同受益人或干预时点的候选机会，找一个其答案能区分它们的问题。例如，店主有意多摆面包，而用户希望剩余面包有人吃掉，这时可用“邻居打烊前买走，算解决了你在意的事吗？”检验目标。沿用每轮一问，随用户的回答保留、修正或放下相应方向。

当能说清希望为谁改变什么结果，以及下一项投入决定时，就开始研究。用户暂时不知道的市场事实交给研究，确实取决于用户取舍的事项留给下一轮。方向已经明确时直接沿用。若目标、首个客群或付费方改变，仅对受影响的部分重新定界。

## 从证据到选择

按[研究分工与决策方法](references/research-plan.md)选择能解决当前分歧的专家、工具与材料。可独立的问题在支持且允许的环境下并行，其余由同一 Agent 顺序完成。由产品经理把实际取得的渠道、付款与履约材料放到同一对象和期间上核对，再决定哪些数量可以进入模型。只报告实际读取、检索、推导和执行的工作。

本轮先给初步发现、可行方向、当前推荐，以及会推翻它的证据。解释不同选择将如何改变范围、渠道、定价或交付；遇到影响显著的分岔，只把最重要的一项交给用户选择，等其回应后再深化。常规细节以暂定假设推进。维护简短决策记录，可用以下列名：

| 编号 | 已确认选择 / 待验证事实 / 未决问题 | 内容、日期与依据 | 若改变会影响什么 |
| --- | --- | --- | --- |

记录“用户选择了某个方向”和“市场上确有这种需求”各自的依据。给影响决策的数字和判断标注证据类型、链接或文件名、发布日期或数据期间。资料冲突时核对人群、样本、定义、地区、分母及时间；仍有冲突就保留差异，说明需要什么新证据。工具、网络、文件或执行能力受限时，写清完成到哪一步、哪个结论因此悬而未决，继续用有依据的上下界、反推条件或可执行实验推进。

## 从选择到草案

- **需求与市场。** 说明谁在什么场景使用、谁决定购买、谁出钱。以现有做法为起点，估算起步渠道在指定地区和期间能触达、转化并交付的客户量，核对单位、重复触达及容量上限。
- **竞争与行为。** 比较直接竞品、间接替代和维持现状，用可追查的价格、采购步骤、切换成本或真实反馈解释改变的动机。把尝试、购买、留存、退出的心理解释落成可证伪假设。
- **商业与财务。** 比较有实质差异的收费与交付方案。选定核算单位，从价格、交易量、留存、退款、分成、履约、获客和收付节奏推到收入、贡献毛利、盈亏平衡和现金投入。展现保守、基准、乐观三种情景以及会翻转建议的临界值。按 [测算与证据脚本说明](references/calculation.md) 选用工具。数据采集、清洗、统计、建模、敏感性分析和研究制图的新增脚本一律用 Python。若业务机制不同，调整模型并保留本次源码和口径。
- **执行与反证。** 评估技术、运营、渠道、资源与适用的合规约束。把影响大且证据弱的假设排在前面。正式建议前，从反方挑出一个最可能推翻建议的前提，写明证伪信号和决策变化。区分数据口径冲突、尚待验证的事实和决策者偏好。
- **核实建议。** 按研究方法中的“逐项复核决定性依据”回到原始材料，核实每个足以改变建议的主张和参数。把证据实际支持的范围、仍需满足的条件及对应投入写进摘要。修改关键前提或提高建议的投入规模时，复核受影响的结论。
- **提交审阅。** 先交付一页决策摘要、九格商业画布草案、关键测算和最大不确定性。指出当前等用户审阅的具体事项，停在草案。用户修正前提时，追踪受影响的市场容量、行为预测、付费与计价、渠道、现金模型、画布和建议。重跑计算，说明改前和改后的结论，再提交受影响的草案。

## 从确认到交付

将已审阅的分析保存在独立于主题的简报中。章节名、顺序和篇幅由投入决策决定。财务分析可以只有一页，也可以用数页展开单位经济性、现金时序和翻转条件。模型数值、单位、引用和不确定性随其论点保留。画布保留一页九格，长论据在分析页或证据附录展开。

**先看样张，再选主题。** 内容获准定稿后，按[报告制作与核对](references/slides.md)运行 `preview_themes.py`，只用本次首页和商业画布生成董事会简报、资本市场路演、战略研究三套预览。给用户预览入口，请其选择主题并等候回复。仅认可内容或回复“OK”不能推出主题选择。用户已经明确指定主题时沿用其选择。若变更内容影响结论，应先更新分析和预览。用户只改风格时直接复用原稿与模型。

**生成正式报告。** 取得主题选择后才运行 `render_report.py --theme …`，交付独立的离线 `report.html`。保存简报、模型、证据和所选主题标识以便复现。报告的版式与演示行为由 skill 资源提供，撰写分析时无需生成 HTML 或 CSS。

首页明确建议、决定性依据、最大不确定性与翻转条件。内嵌标准九模块画布，逐项核对客群、渠道、价值、付费方、收入及成本与模型一致。多边平台还要交代各方交换什么价值、哪一侧先启动。附录载明证据、参数、期间与公式，末页列出优先实验、投入、通过和停止阈值。报告可在新对话独立阅读，写出产品与日期或版本、已确认范围、约束、成功指标、未决事项及可引用的页标题。

交付实际文件路径，并按当前客户端给一条填入该路径的 bxp 调用示例。Codex CLI 用 `$bxp 根据 … 编写第一版 PRD。`，Antigravity App/CLI 可用 `/bxp 根据 … 编写第一版 PRD。`，Gemini CLI 或客户端不明时用“使用 bxp，根据 … 编写第一版 PRD。”，然后结束。用户单回“OK”只确认本轮的审阅对象。方向获准就继续分析，草案获准就进入选主题，正式报告获认可就收束。进入 PRD 须有明确的编写指令。
