# 从调研台账到可复核的测算

两个脚本使用 Python 3.9+ 标准库。先用可用的检索或文件工具读取原始资料，再将会改变判断的证据登记到 CSV。脚本规范字段、链接台账并复算结果。附带的[台账](../assets/example/evidence.csv)和[参数](../assets/example/model.json)均为合成示例，包括决策线。运行真实项目时使用该项目自己的输入文件。

以下示例从项目根目录执行，技能安装在 `.agents/skills/bxf`。实际运行时，从当前加载的 `SKILL.md` 路径确定 `skill_dir`；客户端工作目录与项目根目录不同时，用绝对的技能和输出路径。输出目录可按本次项目更换。

```sh
skill_dir=".agents/skills/bxf"
output_dir="reports/食材损耗示例"
python3 -B "$skill_dir/scripts/research.py" "$skill_dir/assets/example/evidence.csv" "$output_dir/evidence.json"
python3 -B "$skill_dir/scripts/model.py" "$skill_dir/assets/example/model.json" "$output_dir/evidence.json" "$output_dir/results.json"
```

## 证据台账

[research.py](../scripts/research.py) 读取一个 UTF-8 CSV，写出含 `records`、`duplicates_removed` 和 `warnings` 的 JSON。第一行须含完整字段，次序可调。

| 字段 | 填写方式 |
| --- | --- |
| id、topic | 给每条证据稳定编号。主题包含需要比对的统计对象及地区。 |
| kind | 可核查事实、外部估算、用户输入、模型推断、待验证假设，五选一。 |
| claim | 保留原文要点、总体、样本与分母。写清推断依赖的证据或要如何推翻假设。 |
| source | 原始链接或可定位的文件名与页标题。用户选择可记对话日期和原句；假设可记提出它的记录。 |
| period、unit | 填数据期间或发布日期及单位。定性记录显式填“定性”。未知期间写“期间未披露”，说明它如何影响可比性。 |

同一编号完全相同的记录仅保留一次；同号异文、缺失字段会报错。不同编号即使表述接近也保留。相同主题和期间的不同单位或表述会在 `warnings` 中列出，交给研究者核对定义、样本、时间和换算依据。重复报道引用同一原始数据时，在形成建议前合并证据权重。关键数据无法取得时，可用带证据的区间或反推临界条件，标明未知量如何影响决策。

## 模型输入

[model.py](../scripts/model.py) 读取一个业务参数 JSON 和清洗后的证据 JSON，生成一份三情景结果。适用于从零获客、逐月计费、以客户为核算单位的订阅业务。选模型前先写清谁在什么事件后付款，以及交付、收款各发生在何时。按单业务按成交单量、客单价、退款和逐单履约成本推算。双边平台分别估计供需两侧的有效量，按实际可撮合成交额与抽成计算平台收入。库存、账期、押金或税费占用资金时，将对应收支放入实际期间。遇到这些情形，在报告工作目录另写或改写 Python 模型，保留来源、单位、三情景与收付公式，并适配展示字段。以一个手算案例核对收入、成交上限和现金结余。

- `business` 填产品、客群、使用者、付费方、渠道、计费方式、货币代码、地区、期间、正整数月数，字段名见示例。期间列出起止月份，核对与月数一致。使用者、购买决策者和付费方有差异时，在报告交代采购关系。
- `parameters` 每项显式填写 `base`、`optimistic`、`conservative`、`unit`、`source`、`period`。数值为非负 JSON 数字；比例用 0–1，账期用整月。对三个点位分别说明依据、适用期间和不确定性。一个参数的各情景来自多份资料时，新增一条综合证据，列出各点位与原始证据编号，再填其编号。
- 对足以翻转建议的参数，沿 `source` 回到原文或计算底稿，逐项核准对象、数值、单位与适用期间。设想的报价填作待验证假设，客户已签订单才可用于支持相应客户的成交价。对照落款与付款记录再判断是否到账。
- 货币单位随 `currency` 替换，例如 `CNY/客户/月`。触达线索按每期新增、互不重叠的潜在付费组织计。同一总部下的门店不可重复计为客户。
- `onboarding_capacity` 限制每月新接入客户，`active_capacity` 限制并行服务客户。留存、转化与容量共同决定活跃数，小数代表统计期望。零转化和零交付能力都可输入。
- 当月账单先扣退款，再按净收入付平台分成。履约费随活跃数发生；退款、分成和客户回款按同一账期结算。固定费与获客支出当月支付。期初启动支出单列。当月现金按净额结算，日内资金压力、坏账、期后续营需单独建模。

## 结果及解释

结果保留 `business`、带来源与期间的 `assumptions`、可附录引用的 `formulas`，以及按 `base/optimistic/conservative` 区分的 `scenarios`。每个情景包含：

| 字段 | 用法 |
| --- | --- |
| inputs、monthly | 原始数值与逐月留存后活跃、实际新签、净收入、贡献、获客支出、经营结果。仅在展示层设置小数位。 |
| cash_schedule | 从期初启动支出，经各月收支，延伸到期末应收应付全部结清。每条有月序、流入、流出、累计余额，初始可用资金假定为零。 |
| summary.new_per_month、new_total、ending_active | 前者是每月漏斗和接入能力允许的新签量；实际累计新签与期末活跃还受并行服务上限影响。 |
| summary.net_revenue、contribution、operating_result | 分别是全期退款后收入、扣除平台分成和履约后的贡献、再扣固定和获客支出后的经营结果；经营结果不含期初启动支出。 |
| summary.peak_cash_need、unit_contribution | 按最低累计现金得出的所需期初资金；每活跃客户月贡献的金额。 |
| summary.break_even_active、break_even_price、notes | 固定期末月实际新客量与各项成本，前者反推当月经营保本所需整客户，后者在既定活跃量反推临界月价，向上取分。无有效分母时阈值为 null 并给说明。容量不足也会提示。 |

敏感性分析要说明哪一条业务决策会被阈值改变。例如，比较客户接受的真实报价与期末单月临界价格，同时检查付费方人数、容量、资金缺口和全期经营结果。若关键不确定性是其他变量，复制项目参数文件，保持其余输入不变，逐档更改该变量及依据后重跑。图表、画布、财务页从同一次运行的 `results.json` 读取数值，文字写明口径与阈值的适用条件。

脚本遇到缺失值、单位不匹配、证据编号失效或非法比例时以非零状态退出并说明原因。先补齐或修正参数，再重新生成结果。不得以旧结果代表已修订的客群、付费方、渠道或价格。若无法执行，标出未经计算或未复核的数值与决策影响，保留公式和可运行输入。
