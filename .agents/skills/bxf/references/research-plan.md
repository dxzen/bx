# 研究分工与决策方法

资深产品经理先写一句待决问题（例如“用现有渠道做三个月付费试点是否值得”）。给每个实际启用的角色分配独立问题和材料；由同一 Agent 兼任时也交付相同内容。下表是可调用的研究分工。只在执行过相应工作时陈述发现。

| 角色与问题 | 需要的输入 | 可用工具与方法 | 交付什么 | 什么决定可能改变 |
| --- | --- | --- | --- | --- |
| 产品经理：决策者在比较哪两种投入？ | 用户目标、可用投入、不可逆成本、已确认与未决事项 | 文件读取、对话记录、决策表 | 写清比较基线、取舍依据、最大反证与建议 | 推进、限范围试点、补证或暂缓 |
| 市场研究：首批客户有多少，今天的替代品怎么买？ | 地区、期间、单位、渠道名单或样本、采购链 | 联网查原始统计、官方价格与合同条款，读取材料，用 Python 去重、统一口径 | 当前工作方式和竞品对照、可达客户的自下而上区间、来源 | 优先客群与市场进入顺序 |
| 商业策略：谁愿意为什么结果付多少钱？ | 受益者、预算持有人、购买频次、竞品报价、渠道及各方激励 | 定价资料、报价记录、比较不同计价单位与交付方案 | 各方案的付费理由、计价、频次、获客及交付路径、成立条件与取舍 | 买单方、计价方式或渠道 |
| 财务建模：在什么规模、价格和账期下值得投入？ | 可触达量、产能、转化、留存、退款、收付条款、现金预算 | Python 建模、三情景与单变量反推 | 每单位贡献、期间现金缺口、盈亏平衡、翻转阈值和公式 | 投入上限、试点规模或停止点 |
| 消费者心理与用户研究：用户何时会改变既有做法？ | 实际情境、现有行为、价格、使用者与付款者的利益差异 | 读取已有访谈、行为数据和已授权的一手材料，设计实价试点、队列或对照实验 | 可证伪的行为假设、替代解释、验证办法 | 价值主张、购买流程、留存设计 |
| 技术与运营：能否在时限、资源与约束内持续交付？ | 依赖系统、人员、履约量、关键数据、适用地区 | 阅读技术和运营资料、官方规则，推演产能与失败路径 | 瓶颈、交付上限、最低试验方案、失败时的处置 | MVP 边界、合作或自建、是否启动 |

## 把各角色的发现放到一起核对

分工时先约定本次要决定的投入，以及各角色结果能用什么联系起来。例如研究上门服务，市场研究用渠道名单按客户去重，交付可定位的线索清单。商业策略用报价单、付款及退款记录区分询价、承诺和净实付。用户研究从具体经历中提取原话、随后发生的行为及其他可能解释。技术与运营按排班、路线或实际工单检查哪些订单能在约定时段完成，给出工时、失败原因和补救成本。选与本次决策有关的工作执行，交回所用材料、操作及结果，缺材料时说明可以验证到哪一步。

产品经理让财务按同一客户、订单或其他适当单位，核对地区、时间窗口和状态，找出可触达、有购买行为且能履约的交集，再将可用数量和成本带入模型。同一原始记录被多个角色引用时只计一次。资料只能提供各自汇总数时，说明最多可能重合多少、至少已证实多少，将补充哪项记录写清。对新证据重新核对受影响的对象，保留原先的判断与改判理由。

## 如何衡量证据

每条关键证据分配稳定编号，保留主张、证据类型、来源链接或文件名、发布日期或数据期间，以及适用人群、单位和限制。优先实际记录、原始统计、企业披露、官方定价和一手研究。区分**可核查事实、外部估算、用户输入、模型推断、待验证假设**。访谈意向、实际下单和续约是三个独立观察。资料未能取得时明确写“未知”，用阈值形式表达条件。例如，用剩余现金与每次实验可承受的成本决定样本上限；把需要核实的报价或转化率列入实验。避免用任意中位数填补缺失。

对行为假设至少写出人群、场景、可观察行为、竞争解释与证伪办法。例如，“若店长担心上报损耗会被扣分，免于追责的试点应提高持续填报率”；录入耗时也可能解释同一现象。通过分别改变追责说明和录入时长区分两者，事先确定观察窗、分母和行动阈值。只在有原始观测时写回结果。

## 逐项复核决定性依据

优先核对那些一旦撤回，就会改变客群、投入、盈亏判断或继续条件的主张。请另一角色从原件复核。由同一 Agent 兼任时，也要重新打开原文、明细或原始计算输入。在现有台账或草案中为每项留下简短记录：

| 主张或参数 | 原件定位与直接观察 | 从材料到结论的推导及适用边界 | 对投入决定的影响 |
| --- | --- | --- | --- |
| 某客群接受拟定报价 | 订单行、报价页或访谈段落，辨明谁在何时对什么作了何种承诺 | 核对对象、单位、分母、期间与退款状态，写清材料能支持的数量或区间 | 若只能查到报价，保留价格为试算值，先验证对应人群实付 |

编号有效只说明能找到台账记录。原件与主张无关时撤下引用，改用直接支持它的材料。只支撑一部分时缩小表述或拆开事实与推断。尚无材料时把该项改为假设，指出哪种可观察的结果能补上缺口。将变化同步到测算、画布和首页建议。区分能支持一次有限试验的依据与能支持扩大的依据，明确本次最多承诺哪一笔投入。

## 支撑决策的核对

1. 把可触达的去重客户数乘以各步转化率，再受销售、签约、实施等瓶颈约束。确认客户、门店、订单与合同的换算。逐步标明地区、期间、单位与来源。
2. 把客群、决策者、渠道、价值、付费理由、频次和成本串在一起。比较方案时说明在何种证据下另一方案更合适。检查现金最低点及账期，避免把应收当现金。
3. 用“前提 / 对建议的影响 / 证据强弱 / 如何推翻”排列风险。优先实验写明对象、方法、周期或预算、指标、阈值、通过后的投入与失败后的停止或改向动作。
4. 发生分歧时先对齐样本、时间和分母，再找可区分两种假设的观测。如果剩下的是风险偏好，说明不同选择的代价，交给决策者。用户确认只改变决策记录的状态；事实与模型保留各自来源。
