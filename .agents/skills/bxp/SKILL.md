# bx · PRD 制作

交付依据明确、可以据以设计、实现和测试的产品需求文档。普通反馈延续本阶段，沿用已选报告与已确认的修改。运行需要报告读取工具和输出位置的写入权限。默认 Markdown 只需本地文件工具，其他格式或附件使用环境中对应的读写工具。

## 调用与资源定位

技能名称为 `bxp`。Codex CLI 的 `$bxp`、Gemini CLI 中“使用 bxp …”的提示词，以及 Antigravity App/CLI 的 `/bxp` 或点名调用，都沿用下面的流程。

本文件的相对链接从所在技能目录解析，模板按当前加载的 `SKILL.md` 路径定位。报告和交付目录以本次项目及用户指定的位置为准，使用当前客户端可用的文件工具。

## 选择报告

1. 用户指定文件或附件时直接读取，包括其他工具或项目生成的报告。明确要求据此编写即表示已选定，无需再次确认。阅读报告正文、表格和附录；报告自身足以交接，不要求上阶段对话、计算文件或特定 HTML 结构。
2. 用户仅调用本技能，或说“刚才那份报告”，若本对话能唯一定位刚交付的正式报告，直接使用。仅回复“OK”或认可报告，只确认当轮审阅事项。
3. 无报告、指定文件无法读取或多个候选无法区分时，说明具体缺口，只问一个可解决定位问题的问题，然后等待。若有两个版本，可在问题里列出两个文件名供选择。以用户选择为准，勿自行选最新文件或改用项目里的示例。

## 界定本版工作

从真实章节或页标题摘取客群、使用者、购买者与付费方、关键场景、计价及交付约束、报告建议、范围内外、成功指标和未决假设。保留版本或日期，报告未标注时如实写明。沿用已有调研和测算，标清哪些是模型条件、哪些是已确认决策。

限定试点就只写实现、观测试点所需的最小流程。建议补证或暂缓时，按报告写验证目标和继续或停止的条件。报告建议暂缓但用户要求完整开发时，指出具体冲突，只问本轮需要描述验证实验，还是采用用户另行决定的开发范围，等待答复。若用户已明确覆盖原决策及新范围，直接记录变更与影响。

只补充会改变范围或验收的缺口。可推导的交互和异常处理作为设计决定注明理由；未验证的事实保留问题、验证办法与受影响需求。决定分歧实质上阻塞编写时，集中询问当前最需要决策的一项。

## 编写和复核

按[评审模板](assets/prd.md)组织文档，以具体产品内容替换占位符。每项核心需求给出优先级、角色、条件、操作、可观察结果和可回查的报告定位。针对真正可能发生的异常，写出反馈、业务状态和恢复方式。指标写明统计对象、窗口、数据来源和预设阈值；报告未给阈值时注明待定及其决策影响。

交付前从报告逐项核对付费方、计价单位与频率、MVP 边界、约束、指标口径和阈值。沿主流程走一遍，再走一遍会影响业务结果的异常分支；检查每项核心需求都能凭文档独立编写测试用例，引用能定位原文，设计推导和未决事项各有标记。样例或试算报告里的假设须保留原有标识。

用户指定格式、文件名或位置时依其要求。默认写入源报告同目录的 `PRD.md`；只有附件而无可写源目录时，写入当前工作目录并说明位置。交付实际落盘路径，简述本版覆盖的范围和仍待产品决策者拍板的事项。
